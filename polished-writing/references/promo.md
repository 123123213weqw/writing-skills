# 开源/产品宣传(promo.md)

受众:开发者/潜在用户。得体 = 自信、可验证、不吹。开发者对营销腔零容忍,信任是唯一货币。

## 主线:差异点,不是功能清单

- 开头一句定位 + 一句"和主流方案比它站哪"(直接点名竞品,别回避)
- 正文 = N 个"它做到、别家(以其形态)做不到"的差异点,每个:一句机制 + 一张真实截图/数据
- 功能清单放文末速查表,不占主线
- **失败案例教训**:把对比写成礼貌的七维表 + 自曝短板,读者只记住"没赢还慢"——差异点必须是主角,不利数据要么放次要位置给正确解读,要么删

## 证据等级

1. 真实截图(界面/运行画面)最强——标注"本机真实运行"
2. 对照实验数据(注明方法学与 p 值的正确解读:"统计上无法区分" = "等价",不是"没赢")
3. 公开可查事实(竞品对比只用这层)
4. 自己的宣称(最弱,能不用就不用)

## 语言规则

- 每个卖点配"为什么难做到"的一句技术原因(证明不是没想过)
- 承认局限反而加分:"仍在快速迭代""Web UI 引用了 XX 组件并保留许可"——写清楚,别藏
- star CTA 一次就够;issue 邀请比 star 邀请更显开放
- 不写"生产级""企业级",除非真有 SLA

## README 附加规则

- 首屏:一句话定位 + 徽章 + 三行 quickstart;对比表放"Why"小节
- 截图放首屏后第一屏内;没有截图的 README 转化率减半
- 中文 README 与英文保持结构一致,不是逐句直译
